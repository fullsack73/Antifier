# 후보 부분 갱신의 진행률 분모 보정

- 발견: 2026-11-14 고정 예측 지도 백테스트 진행 화면
- 증상: 부분 갱신에서도 `2024-11-15: ARIMA_TRANSFORMER PPL (65/457)`처럼 전체 유효 풀 크기를 분모로 표시해 전체 재예측으로 오인하게 한다.

## 확인된 원인

`src/backend/candidate_search.py`의 예측 진행 콜백이 실제 평가 집합 대신
`len(universe)`를 전달하고, `src/backend/strategy_backtest.py`가 이를 그대로
`(done+1/total)` 메시지에 사용한다. 실제 후보 선정과 전체 지도 갱신 여부는 별개이며,
확인한 고정 지도 작업의 완료 기록에서는 초기 457종목 외에 전체 갱신이 없었다.

## 수정 범위

- 초기 전체 계산·정기 전체 갱신·부분 갱신을 진행 메시지에서 구분한다.
- 부분 갱신의 분모는 해당 단계의 실제 선정 집합, 전체 갱신의 분모는 해당 전체 평가 집합으로 표시한다.
- 전체 풀 크기는 별도 참고값으로 표시하고 처리 대상 분모와 혼동하지 않게 한다.
- 처리 수가 캐시 적중을 포함하는지 명시하고, 신규 예측 호출·캐시 적중 수를 구분한다. 모두 캐시 적중한 단계도 완료 상태를 표시한다.
- 후보 선정 전 전체 지도를 계산하는 단계와 선정 후 현재 예측 단계를 구분해 진행 수가 역행하거나 중복 집계되지 않게 한다.
- 기존 job 진행률·취소·재연결을 유지하고, 필요한 한국어·영어 문구를 함께 갱신한다.
- 후보 정책·실제 평가 집합·예측 캐시·거래 로직은 변경하지 않는다. 이미 실행 중인 작업은 중단하거나 설정을 바꾸지 않는다.

## 완료 기준

- 457종목 풀에서 40개만 평가하는 fixture의 진행 분모가 40이며 457로 표시되지 않는다.
- 고정 지도는 초기 이후 부분 평가로, 주기 지도는 갱신 시 전체 평가로 표시한다.
- 캐시 없음·일부 적중·전부 적중에서 처리 수와 완료 표시가 실제 평가 집합과 일치한다.
- 백엔드 콜백과 프론트엔드 진행 메시지 회귀 테스트로 검증한다.
